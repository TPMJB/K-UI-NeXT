# Library compatibility table

One row per game in the owner's library uploads, generated by
[`tools/library_compat_table.py`](../tools/library_compat_table.py). It runs
each startup through the production checks the launcher uses, in its own order,
and joins the console results already recorded in
[`evidence/library-console-results.json`](evidence/library-console-results.json).

- **Background X/Y + virtual VMU:** the compact Background module (72 KiB VMU
  worker, 284 KiB lease) admits the game: its structural gates pass, or the
  game has a reviewed fixed arena, and it has the SDK SCI family the reader's
  interrupt route needs.
- **Without VMU:** when Background refuses, New falls back to the standalone
  reader if the SDK SCI family exists.
- **Blocker:** the first gate that refuses.
- **CD music:** the contract the launcher selects for discs with high-density
  audio tracks. Native CD music admits only the exact Toy Commander and MDK2
  executables; Windows CE CD music only the four exact profile kernels; Smash
  Pack has its own route. Any other disc plays with CD music Off. Audio tracks
  do not prove the game streams CD audio.
- Ordinary Standard launches with VMU Off have no static gate, so every native
  game is expected to boot that way; plain Windows CE launches do not depend on
  the kernel. This table is about the added services.
- Static gates are necessary, not sufficient. "Known limit" marks a blocker the
  roadmap or disc layout shows that the static model does not check.

## What it says

- **20 games pass the Background virtual-VMU gates, and the owner has tested
  them on console.** The console column cites each recorded result. A blank
  cell means only that the evidence file holds no result, never that the game
  was untested: search the docs before claiming that.
- **Known limits from the integration roadmap's section 3 are not
  owner-confirmed.** Its Sonic Adventure line ("executable-loader and exit
  lifetime still block shared VMU") is wrong: the owner reports Sonic
  Adventure working with the Background reader and virtual VMU, and Silver
  working with virtual VMU. Treat the remaining entries from that table as
  claims to confirm.
- **Dead or Alive 2 works with virtual VMU on the Background loader without
  prefetch**, a combination this table does not model: it checks only the
  combined module that also carries the 192 KiB read-ahead cache, which DOA2
  refuses (owner: Background plus prefetch did not fit in RAM).
- **Blockers among the 16 native startups (15 games) without a Background route:**
  - Maple driver family unresolved (5 startups, 4 games): Shenmue (two
    startups), Shenmue II, MDK2 and Blue Stinger. Shenmue's three startups are
    one engine, so one family fix may cover both Shenmue games. Shenmue,
    Shenmue II and Blue Stinger also lack the SDK SCI family, so they have no
    New route either: Standard only.
  - SDK heap family unresolved (3): Dead or Alive 2, Frogger 2, Rush 2049.
  - Fixed RAM, needs a reviewed RAM-map plan (2): Crazy Taxi, Spawn.
  - Maple layout unresolved (2): Power Stone, Zombie Revenge.
  - 284 KiB lease does not fit (2): Tony Hawk's Pro Skater 2, Soul Reaver (which
    also lacks the SDK SCI family).
  - One each: Omikron (heap initializer call), Generator 2 (exits; a demo disc
    whose menu starts several games).
- **CD music is the largest missing feature.** 12 native games and Nightmare
  Creatures II have CD-audio tracks and no CD-music profile, so they play with
  CD music Off (where the game uses CD audio at all).
- **Loaders (Quake III, Test Drive Le Mans):** the boot file is a small Katana
  program that loads the game program to the same address and jumps to it.
  The stage binds hooks to the boot file only, so any Background or New
  binding goes stale when the program replaces it; Standard is the safe route
  until the stage rebinds on that load. Quake III's loader itself passes every
  gate, so the launcher would currently admit it on Background. The programs:
  `Q3_USA.BIN` and `INTRO.BIN` stop at terminal exits; `LEMANS24.BIN` at the
  Maple layout and `FMV.BIN` at the heap family. All four have the SDK SCI
  family.
- **Shenmue disc 1 and Skies of Arcadia disc 1** read with v2.1: Shenmue
  disc 1 shares discs 2 and 3's startup, and Skies disc 1 its known one.
  Soulcalibur is an incomplete dump and is set aside.

## Regenerate

```sh
python3 tools/library_compat_table.py Library-startup-*.zip --work PRIVATE_DIR \
    --stage-elf build/native-background-compact/stage.elf \
    --output PRIVATE_DIR/table.json --table PRIVATE_DIR/table.md
```

Then replace the table above with `table.md`. Pass every part from every
upload; runs are merged and repeats listed once. The JSON report holds library
paths and stays private; this table holds titles, product numbers and sizes
only.
