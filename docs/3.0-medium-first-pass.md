# K-UI 3.0 medium-feature first pass

This candidate adds library organization, exact setup recommendations, native
virtual-card history, menu controls, screenshot browsing, read-only LAN
downloads and support-report export. Host tests and source/build checks cover
the implemented paths. **This rebuilt candidate has not been accepted on a
physical Dreamcast.** The next step is console testing, including latency.

## Where to find it

| Feature | Menu path and controls |
| --- | --- |
| Continuous Flow view | **Games → START → Change layout** until **Flow**. UP/DOWN moves through the vertical list across cached eight-row chunks; LEFT/RIGHT moves one visible window. The selected game has a large cover, with an eased viewport/highlight. The chosen layout is saved. |
| Search, region/disc filters, letter jump | **Games → START → Search and filters**. Edit the draft, then choose **Apply filters** or **Jump to letter**. X clears the draft; B leaves without applying it. |
| Display name and custom cover | Highlight a game, then **Games → START → Edit display choices**. Set **Display name** or **Cover image path**, then **Save display choices**. Empty values use the original title/automatic cover. |
| Stable content identity | Highlight a game, then **Games → START → Verify stable identity**. A confirms a complete-image read; B stops. Matching verified content can retain saved launch choices and Favorites/Recent associations after a move. |
| Exact recommended setup | Select a game, then **Y Options → Advanced → Recommended setup**. Review the identity/evidence note; A explicitly applies and saves the recommendation. |
| Virtual-card history | Select a game, then **Y Options → Virtual VMU card**, select the exact existing card and press **START**. In **Save history**, START checkpoints, Y refreshes, X exports, and A opens restore confirmation. |
| Menu controls | **Settings → Controls**. UP/DOWN selects a row, LEFT/RIGHT changes menu repeat or stick deadzone, A saves, X restores normal control values, B returns to Settings. |
| Screenshot gallery | **File Manager → X Actions → Screenshot gallery**. A opens a saved BMP. The existing **L + R + Y** menu capture saves to `/KUI/screenshots`; this gallery adds no in-game capture hook. |
| Phone/PC downloads | **Network → SD card in browser → A**. Open the displayed `http://…:8080/` address on the same LAN. Keep the page open on the Dreamcast; B stops sharing. |
| Support report | **Diagnostics → START** opens **Create problem report**. X selects screenshot inclusion, A exports, and Y opens the SD browser. |

Flow retains the current chunk and two neighboring chunks rather than loading
the entire library. Viewport/highlight animation targets 110 ms; that is an
animation setting, not measured console input latency. At an uncached edge the
outgoing rows stay visible while the storage worker fetches the next chunk.
Frames do no filesystem I/O, and this adds no resident game service. See
[Games Flow](games-flow.md).

Display choices are metadata: aliases and cover paths do **not** rename or
move game folders, images or saves. Stable-identity verification reads the
complete image and can take minutes; it is not part of every normal listing.
Search/jump work on the same query snapshot as the displayed library, including
the active Favorites/Recent selection. Existing favorites, multi-disc grouping,
disc switching and return behavior remain their established features.

## Deliberate limits

- **Recommendations are narrow.** The built-in historical catalogue contains
  exact SCI/GDI identities for Code Veronica, Armada, Bust-A-Move 4, Worms
  Armageddon and Toy Commander. “Tested setup” refers to the historical evidence
  in its note, not this rebuilt candidate or every revision. Toy’s known FMV
  limitation remains visible. The CD music evidence does not certify a virtual
  VMU combination. Explicit saved choices remain in charge. Local imported
  recommendations are always **Experimental** and require Apply; they cannot
  acquire a Tested label. See [game profiles](game-profiles.md).
- **History is for the SD image launcher’s native virtual-VMU path.** It does
  not add automatic history to physical VMUs, physical GD Play, or WinCE/CDDA
  paths. A pre-launch checkpoint and a later **Previous session** checkpoint
  use the recovered card/journal boundary; they do not prove a whole-game save
  was atomic or a return was clean. VMU Off skips automatic history. Restore
  creates a new verified card and keeps the original. The latest eight complete
  versions per game are retained; identical data is deduplicated. See
  [virtual VMU history](vmu-history.md).
- **The browser downloads exports only.** It shares screenshots, completed
  support reports and explicitly exported saves, with no upload, delete,
  settings editor, updater, arbitrary filesystem view or live-card access.
  FTP and HTTP use the same exclusive storage/network worker. SCI network
  hardware requires that SCI is free for it; the usual pairing is SCIF storage.
  See [browser companion](browser-companion.md).

This pass adds no compressed-image loader, IDE work, large installer,
enhancement packs, homebrew browser/launcher, or new in-game runtime service.
It does not change the resident loader or promise broader game compatibility.

## Install by copying one file

1. Power off the Dreamcast and put its SD card in your computer. Keep a copy of
   the current working `KUI/runtime.kui` as your rollback file.
2. Copy the supplied **`KUI/runtime.kui`** onto the card at that exact path,
   replacing that file. Keep the rest of your existing KUI installation:
   loader modules, games, preferences, profiles, virtual cards and saves.
   Do not replace the entire `KUI` directory or run a separate installer.
3. Eject the card normally, boot K-UI and test the menu features first.

To roll back, power off and restore the previous `KUI/runtime.kui` at the same
path. Runtime rollback does not undo settings, exported reports, checkpoints or
new cards explicitly saved during testing. Preserve those files when reverting.

## Physical-console acceptance

Use the same card and existing working modules for before/after comparisons.
Record the candidate build, storage transport and selected game/setup.

1. Confirm normal Games opening, D-pad selection, Favorites/Recent, disc groups,
   return and disc switching still behave as before. Measure first-page and
   repeat-page latency; compare Normal/Slow/Fast repeat and stick deadzones.
   In Flow, hold/reverse UP/DOWN quickly across eight-row boundaries, test
   LEFT/RIGHT and the final partial chunk, then repeat with Favorites, Recent,
   search/filter, letter jump and disc sets. Check selected-cover correctness
   and selection after Details/Back. Record uncached-edge waiting separately
   from the 110 ms animation.
2. Apply and cancel searches/filters; jump to a letter; change one alias and
   cover, restart, then reset them. Check that the files retained their names.
   Run stable-identity verification explicitly and test B cancellation.
3. Review a supported exact recommendation and an unmatched title. Preserve a
   custom saved choice and verify it wins. Treat imported recommendations as
   experimental. Re-test launches rather than inferring compatibility from a
   profile label.
4. For an already working **native SD virtual-VMU game**, measure pre-launch and
   previous-session checkpoint time. Save in game, return/reboot after saving,
   list history, export, then confirm restore to a new card and load it. Verify
   the original remains selectable. Repeat with VMU Off and check that no
   automatic history job runs. Physical console latency is still unmeasured.
5. Open a menu capture in the gallery. Test browser list/download and B Stop
   using the installed W5500 or Wi-Fi adapter. Create a report with screenshot
   inclusion on and off, download its files and cancel one export with B.

Keep a [support report](support-reports.md) for any failure or noticeable new
delay. Report the exact menu action and elapsed time; a photo/video can record
console behavior that a preparation log cannot prove.
