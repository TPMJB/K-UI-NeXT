# Evolution: mixed-port polling correction

The previous `3a143db9cf2e` candidate froze in NORMAL and RAW mode on the console.
Its fast path required every descriptor to be a controller GETCOND request. That
condition did not match the usual one-controller setup. RAW also retained the
full C validation path, so it was not a test with only an empty gateway active.

Executing the original Evolution initializer, submission code and response
consumer established the actual recurring batch: controller A GETCOND plus
DEVINFO queries for empty B-D (B-C on the older modeled ASIC revision). With
virtual A1 advertised and INFO replies generated by the production emulator,
the SDK enumerated A1 once and then returned to the same mixed main-unit batch.
The revised path accepts that batch generically. No Evolution video code or
scanline wait is changed.

## Install and primary test

Extract into a fresh folder and run:

```sh
python3 personalize.py /run/media/apollonius/Dreamcast --profile KUI/vmu-test/p0005/retail-persistent-profile-0005.bin --game evolution1
```

This installs directly and preserves the prepared card files. No backup/restore
script is required. Use the same Evolution image, SCI/Standard, Auto encoding
and controller arrangement. Keep physical A1 unplugged and the same CDDA,
background-loading and RAM-patch settings used for the previous comparison.

Test the opening FMV, menu, new-game/save, power-off and reload. Normal mode
has no live counters or automatic diagnostic stop. Console success is still
required; host results do not establish that Evolution's freeze is fixed.

## If the same black screen remains

The package also contains a focused optional measurement; no further build is
needed. Personalize again with the same command plus `--profile-runtime`:

```sh
python3 personalize.py /run/media/apollonius/Dreamcast --profile KUI/vmu-test/p0005/retail-persistent-profile-0005.bin --game evolution1 --profile-runtime
```

Launch Evolution. At the black screen, hold **B and both triggers fully down**
for two seconds, then release. If controller interrupts are still running,
a capture starts after 30 polling pairs. After about 20 seconds or 1,200 pairs,
it intentionally stops and cycles through the timing and phase pages.
Photograph every page, then power off. A failure to reach these pages is also
useful information; this method cannot report once controller callbacks stop.

PROFILE now takes the same fast/full paths as NORMAL. Its first page reports
fast versus full counts. Exact Evolution phase records include active video
registers, entry/exit scanlines and clock ticks, and interrupted PR/SPC/SSR only
when the entire original IRQ caller chain validates. Invalid samples fail
softly. Normal mode performs none of these phase reads. The profiler adds work;
its C-body timings are not whole-interrupt timings or proof of identical NORMAL
behavior. There are no additional game patches, timer interrupts, live VRAM
writes, or video-blank deadlines in this measurement.

## Evidence and limits

- The original SDK replay executed 1,200 DMA batches in ten cases, including
  actual production C INFO replies for virtual A1. In each virtual-A1 case,
  rounds 0-1 performed initial enumeration and rounds 2-119 qualified for the
  mixed fast path. This covers automatic SDK polling, not every game-generated
  request or real interrupt scheduling.
- The representative 52-byte batch uses 142 guest reads per pair, versus 314
  for the previous build and 309 for the current full reference. Read counts
  are not measured console time. Source DMA and all unrelated RX bytes remain
  unchanged; only A's presence byte is published after complete validation.
- VMU/subunit requests, unsupported traffic and cold layouts retain the full
  filtering/storage path. Full storage and free-hook ownership guards remain.
- Grandia II, Skies and SA2 contain the same exact-zero scanline wait. Their
  analogous second graphics setup explicitly bypasses it; Evolution's does
  not. Added interrupt latency could therefore affect Evolution differently,
  but the actual starvation explanation remains unconfirmed on hardware.

The archive includes reproducible tests and an optional cloneable source
checkpoint. It contains no game executables. Other comparison flags remain
exclusive: `--control`, `--lease-only`, `--hooks-only`, `--raw-chain`, and
`--evolution-trace`. RAW remains a full-validation comparison. The old live
trace changes timing and is not needed for this primary test or phase capture.
