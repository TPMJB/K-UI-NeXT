## Historical single-variable test

Change `KUI_SCI_STREAM_TOKEN_SLICE` from 256 to 512 bytes. The hypothesis
is that fewer token-search continuations can reduce service/wakeup overhead,
in exchange for longer bounded polling bursts. Hardware playback determines
whether this trade improves ARMADA; it is not a claimed synchronization fix.

Keep the same shared entry budget, pending search state, explicit CE wakeup,
original total timeout, bootstrap/PIO exemptions, payload byte loop, CRC,
recovery policy, resident guards and suppressed live overlay. No artificial
audio delay or menu change accompanies this test.

Cold boot and repeat ARMADA's intro with the same settings and similar run
duration. Compare smoothness and capture its menu-return screen. A brief
Worms boot/intro synchronization check is sufficient; no separate photo is
needed unless a new fault occurs.
